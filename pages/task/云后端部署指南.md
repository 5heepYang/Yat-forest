## 四、云数据库建库验收（db.js 的 6 个集合）

### ✅ 已修复（2026-11-03 多智能体审查发现的两个 db.js 缺陷）

1. **先删后插非事务**（原 db.js `replaceAll`）→ 已改为 `syncCollection`：确定性 `_id` + `.doc(id).set()` upsert，先写后清。
   - 内容没变的文档直接跳过，变了的原地覆盖，任何时刻云端都是完整数据；写入中断不再可能把集合清空。
   - 迁移期兜底：云端已存在的"随机 _id"老文档会按业务主键（taskId/treeId/itemId…）认回来原地更新，不会插出重复。
2. **云端写放大** → 每次 persist 只写真正变化的文档：
   - 加一条日程 = 1 次写（原实现是 读全量 + 删 4 + 插 5）。
   - 内容完全没变时零写入，实测连加 3 条日程共 3 次云调用。

> 回归测试已入库：`node tools/dbtest.js`（21 项断言：播种 / 增量 / 幂等 / 删除 / 老文档迁移 / 写入失败不清空 / 多用户 _id 隔离）。改 db.js 后跑一遍即可，`tools/` 不会被包进小程序。

> 权限前提：`trees` / `goods` 是全局集合，其他用户改自己没创建过的文档会被"仅创建者可读写"拒绝（**只影响日志告警，不丢数据**）。要多人同时改树的状态，把这两个集合的权限放到「所有用户可读写」。

## 八、新增树木审核（管理员）

新增的树不再直接上地图。**主审核是 AI（Qwen-VL），人工只在 AI 判不过时兜底**：

1. 用户提交 → 照片上云 → 调 `task-ai` 的 `action=review`
   - AI 通过 → `reviewStatus: 'approved'`，直接上地图可认养
   - AI 不通过 → `reviewStatus: 'pending'`，转人工复核（避免误杀好数据）
2. 兜底的人工状态：`reviewStatus: 'pending'`、`status: 'pending'`
   - 只有**提交者本人**能在自己地图上看到它（淡色 marker、标签「待审核」）
   - 其他人看不到；待审的树不能认养（`adoptTree` 拦截）
2. 管理员点这个点位 → 卡片底部出现「驳回 / 通过上架」
   - 通过：`reviewStatus: 'approved'`、`status: 'normal'`，正式上地图可认养
   - 驳回：`reviewStatus: 'rejected'`，**所有人**都看不到（数据保留在集合里）
3. 管理员自己提交的树**免审**，直接 approved（避免自审）

**谁是管理员**：`common/config.js` 里的 `ADMIN_IDS`，当前只有 `u_001`（种子队长账号）。
换人往里加 userId 即可。注意这是**前端判定**，只能挡住正常交互；
真要防作弊得把审核挪进云函数，用 `cloud.getWXContext().OPENID` 校验。

## 九、拍照提醒（notify 云函数 + 订阅消息）

代码已就绪，但**需要你补两个值**才真正会推送：

| 缺什么 | 填在哪 | 不填会怎样 |
| --- | --- | --- |
| 订阅消息模板 ID | `common/config.js` 的 `SUBSCRIBE_TEMPLATE_ID` | 设置周期时不申请授权，只保留页面内提示 |
| **AppSecret** | 云函数 `notify` 的环境变量 `WX_SECRET` | 云调用报 `-501001` 时无处降级（见下） |

> 模板 ID 与 AppID 已内置在 `notify/index.js` 的 `DEFAULT_TEMPLATE_ID` / `DEFAULT_APPID`，
> 不是敏感信息，不用再配；换模板时改这两处即可。**只有 AppSecret 必须走环境变量**。

### 部署时遇到 ResourceInUse.FunctionName

函数是在**控制台**创建的，开发者工具上传时会走"创建"分支，于是报「FunctionName 已存在」。
两条出路：

1. **控制台在线编辑**：函数详情 → 函数代码 → 粘贴 `index.js` 内容 → 保存（保留配置）
2. **删了重建**：控制台删除函数 → 开发者工具右键该函数目录上传（此时是真正的创建）→
   重新加环境变量 `WX_SECRET`（模板 ID / AppID 已内置，只填这一项）+ 超时 20s

> 微信云开发的云函数**没有对外开放的部署 API**（腾讯云 TCB API 看不到微信侧环境，会返回
> `user not exist`），所以只能从开发者工具或云开发控制台部署，脚本/CI 都代劳不了。

### ⚠️ -501001 INVALID_WX_ACCESS_TOKEN

云调用（`cloud.openapi.subscribeMessage.send`）拿不到 token 时会出现这个错，常见于云环境与小程序关联关系异常。
代码内置了**降级通道**：云调用失败 → 自动用 `WX_APPID` + `WX_SECRET` 换 access_token
直连 `api.weixin.qq.com` 重发一次，token 缓存 2 小时。

所以**推荐一开始就把 `WX_APPID` / `WX_SECRET` 一起配上**，省得踩这个坑：

- `WX_APPID`：就是 `wx986e1936b714fb78`
- `WX_SECRET`：小程序后台 → 开发管理 → 开发设置 → 开发者ID → AppSecret（点「生成/重置」查看，**只存在云函数环境变量里，绝不进代码**）

返回结果里的 `mode` 字段会告诉你走了哪条通道：`cloud` = 云调用、`http` = 降级通道。
`noQuota` 是「用户没订阅或用完额度（43101）」，属正常，不是故障。

步骤：

- [ ] 1. 小程序后台 → 订阅消息 → 选用一个「待办/提醒」类模板，记下模板 ID
- [ ] 2. 模板字段（`thing1` / `time2` / `phrase3`）与 `cloudfunctions/notify/index.js` 的 `data` 对齐，
       对不上会报 **47003**
- [ ] 3. 两个地方都填上模板 ID，重新上传部署 `notify`（依赖 `wx-server-sdk`，选「云端安装依赖」）
- [ ] 4. `config.json` 已配定时触发器（每天 9:00，`0 0 9 * * * *`），上传后到控制台确认触发器存在
- [ ] 5. 真机点林地页铃铛 → 设个周期 → 应弹出订阅授权框，同意后才可能收到推送

**已知限制**：拍照周期存在客户端 `wx.Storage`（按树分桶），云端拿不到“谁的树该拍了”，
所以当前是**每天给所有认养了树的人发一条软提醒**。要做精准按周期提醒，
得把 `lastPhotoAt` 也写进 `trees` 或新开集合。

## 十、他人主页的数据口径（为什么有些信息看不到）

`users` 集合是 `_openid` 隔离的，客户端读不到别人的用户文档。所以从地图点进别人主页时：

- **能显示**（从全局 `trees` 集合推算）：昵称、认养的树列表、最高等级、总成长值
- **看不到**（属于私人数据）：碳积分、护林币、勋章、兑换记录、改名入口

想展示更多就得放开 `users` 权限或加云函数代查，属于权限设计决策，当前刻意不做。

## 十一、AI 能力边界（哪些地方真的调模型）

| 场景 | 是否调模型 | 通道 / action | 不通过会怎样 |
| --- | --- | --- | --- |
| 新增树木审核 | ✅ Qwen-VL 视觉 | `review` | 转 pending，等管理员复核 |
| 拍照上报隐患 | ✅ Qwen-VL 视觉 | `hazard` | 直接拒绝，不生成工单、不给积分 |
| 日程凭证核验 | ✅ Qwen-VL 视觉 | `verify` | 驳回态，「换一张凭证重试」，不加分 |
| 林地上传生长实拍 | ✅ Qwen-VL 视觉 | `review` | 拒绝，提示重拍，不发护林币 |
| 林地浇水 / 施肥 | ❌ 不调模型 | — | 虚拟动作：每天每棵树各一次，扣碳积分加成长值 |
| AI 管家建议、树灵对话 | ❌ 本地话术库 | — | 纯文案，不消耗 token |

**隐患上报的两道硬约束**（防薅积分）：
1. 必须带现场照片，没图直接在云函数拒绝
2. 视觉模型必须先判 `isTree`，照片里不是树（截图/文档/室内物品）就拒绝，不生成工单

**兜底原则**：任何 AI 调用失败都会回退本地规则（凭证恒通过、审核看必填项、隐患按树种给话术），
保证断网/额度耗尽时页面不瘫痪——但这时候的"AI"是假的，演示前请确认云函数已部署且额度可用。
