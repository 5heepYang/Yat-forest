## 二、API Key 申请（千问平台 / 阿里云百炼）

1. 打开阿里云百炼控制台（https://bailian.console.aliyun.com）→ 开通模型服务
2. 右上角「API-KEY」→ 创建 API Key，复制备用（格式 `sk-xxxx`）
3. 模型分工（同一个 Key、同一个 OpenAI 兼容接口，见 `index.js` 顶部常量）：
   - 文本 `deepseek-v4.1-flash`：日程低碳分析（实测 2.5s 返回，JSON 稳定）
   - 视觉 `qwen3-vl-plus`：凭证识图（DeepSeek 无视觉能力，必须用千问 VL）
4. 注意：这两个都是**推理型模型**，会先产出思考过程再产出正文，因此 `MAX_TOKENS` 必须给足（当前 1200）；
   给 300 会被思考过程吃光、正文返回空字符串，表现为「总是 fallback」。

## 四、云数据库建库验收（db.js 的 6 个集合）

### ✅ 已修复（2026-11-03 多智能体审查发现的两个 db.js 缺陷）

1. **先删后插非事务**（原 db.js `replaceAll`）→ 已改为 `syncCollection`：确定性 `_id` + `.doc(id).set()` upsert，先写后清。
   - 内容没变的文档直接跳过，变了的原地覆盖，任何时刻云端都是完整数据；写入中断不再可能把集合清空。
   - 迁移期兜底：云端已存在的"随机 _id"老文档会按业务主键（taskId/treeId/itemId…）认回来原地更新，不会插出重复。
2. **云端写放大** → 每次 persist 只写真正变化的文档：
   - 加一条日程 = 1 次写（原实现是 读全量 + 删 4 + 插 5）。
   - 内容完全没变时零写入，实测连加 3 条日程共 3 次云调用。

> 回归测试已入库：`node tools/dbtest.js`（21 项断言：播种 / 增量 / 幂等 / 删除 / 老文档迁移 / 写入失败不清空 / 多用户 _id 隔离）。改 db.js 后跑一遍即可，`tools/` 不会被包进小程序。

> 权限前提：`trees` / `goods` 是全局集合，其他用户改自己没创建过的文档会被"仅创建者可读写"拒绝（**只影响日志告警，不丢数据**）。要多人同时改树的状态，把这两个集合的权限放到「所有用户可读写」。

## 六、回退行为说明（给全队的定心丸）

| 场景 | 行为 |

| 测试号 / 游客模式 | `cloudReady()` 返回 false，直接走本地模拟（现状不变） |
| 云函数未部署 / 未配 key / 模型超时 | 云函数返回 `{fallback:true}`，ai.js 静默回退本地模拟，页面零感知 |

## 七、安全注意

- `DASHSCOPE_API_KEY` 只存在于云函数环境变量 / 云端控制台，**不进代码、不进仓库**
- 本地模拟分支不含任何 key；仓库即使公开也不泄漏
- 费用：按百炼控制台的模型计费（演示调用量为个位数/天，成本可忽略）
